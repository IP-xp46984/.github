<h2>端口设置解决的是「入站」，不是「出站」</h2>
<p>很多人以为端口设置能改变设备的对外地址，实际不能。端口映射改变的是「从外网访问某个端口时，流量被送到内网哪台设备」，不改变设备出网时的源地址。</p>
<p>所以要分清两种需求：让外部能访问进来（入站），和设备出网时显示某个地址（出站）。前者靠端口设置，后者靠源地址配置或代理。</p>

<h2>两种端口需求</h2>
<p>入站需求：要在某个地址上提供服务，外部能连进来。典型场景是自建接口、远程管理、对外服务。出站需求：设备出网时用哪个源地址与源端口。</p>
<p>两种需求的配置位置不同：入站在路由器的映射规则里，出站在设备的网络配置或代理设置里。混在一起调，通常两边都调不对。</p>

<h2>端口映射表怎么建</h2>
<p>每个映射记五项：公网地址、公网端口、内网地址、内网端口、协议。五项写完，映射关系就清楚了。缺任何一项，配置时都要猜。</p>
<p>建议同时记一列「用途」。三个月后回来看，只知道「这个映射指向 192.168.1.12」，但不知道那条是干什么的，排查会非常痛苦。</p>

<h2>一个地址映射多个端口给不同设备</h2>
<p>同一个公网地址上，可以用不同端口映射到不同内网设备。比如某个端口指向设备 A，另一个端口指向设备 B。</p>
<p>这种做法节省地址，但要注意两点：一是端口不能重复，二是外部看到的是同一个地址，只是端口不同。如果业务需要「不同身份」，这种做法不成立。</p>

<h2>多个地址各映射一台设备</h2>
<p>这是「一地址一设备」的常见实现。每个地址的所有端口都映射到一台设备，外部看到的就是那个地址。</p>
<p>配置时建议只映射需要的端口，不要做「全端口映射」。全映射会让设备完全暴露，风险很高。</p>

<h2>端口冲突与占用怎么排查</h2>
<p>表现是映射加不上、或加了不生效。先查端口是否已被其他映射占用，再查目标设备上是否已有服务监听同一端口。</p>
<p>还有一种情况是「加了映射但外部连不上」。按顺序查三层：映射规则是否生效、路由器防火墙是否放行、上游线路是否封锁了该端口。</p>

<h2>开放端口的安全底线</h2>
<p>三条：只开放必要的端口；限制来源地址；不用默认端口与管理口令。三条都做到，能挡掉绝大部分扫描与暴力尝试。</p>
<p>如果服务只给自己用，最稳妥的做法是不对全网开放，只允许指定来源访问。这一条比任何加固措施都有效。</p>

<h2>端口清单要定期清理</h2>
<p>映射加得多了，很少有人回头删。结果是半年后路由器里堆着几十条规则，没人知道哪些还在用。清理方法很简单：把当前映射逐条对一遍实际需求，用不上的先停用观察一周，没有影响再删。</p>
<p>清理的收益不只是减少暴露面。规则少了，排错时能一眼看完，出问题定位的速度会明显变快。</p>
<h2>常见问答</h2>
<h3>端口映射能改变设备出网的地址吗？</h3>
<p><strong>答：</strong>不能。它只影响入站流量的去向。</p>
<h3>一个端口能给两台设备吗？</h3>
<p><strong>答：</strong>不能。同一地址上同一端口只能映射到一个目标，除非用不同的公网地址。</p>
<h3>做了映射外部还是连不上？</h3>
<p><strong>答：</strong>查防火墙、查上游是否封端口、查目标设备服务是否在跑。</p>
<h3>需要开放全部端口吗？</h3>
<p><strong>答：</strong>不需要，也不建议。只开必要的，并限制来源。</p>
